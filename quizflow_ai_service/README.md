# QuizVK AI — генератор квизов (FastAPI + Claude API)

Отдельный микросервис, никак не связанный с основным Django-бэкендом кроме
как через фронтенд: превращает текстовое описание квиза от организатора
(«квиз про историю Древнего Рима, 8 вопросов, для старшеклассников») в
готовую структуру тем/вопросов/ответов через Claude API. Сам он ничего не
сохраняет и не знает о базе данных — сохранение делает основной бэкенд,
когда фронтенд отправляет уже сгенерированный (и, возможно, отредактированный
пользователем) результат на `POST /api/quizzes/`, как и при ручном создании.

## Почему отдельный сервис, а не часть Django

- Он полностью stateless — не бьёт по БД, не подписан на CACHES/Redis
  основного проекта.
- Разные нагрузочные профили: генерация — редкий, тяжёлый по времени
  (secunds, не миллисекунды) запрос к внешнему API; остальной бэкенд —
  частые быстрые запросы к своей БД. Раздельное масштабирование.
- FastAPI + Pydantic здесь удобнее для строгой валидации структуры, которую
  должна вернуть модель, чем DRF-сериализаторы, заточенные под ORM.

## Установка и запуск

Нужен Python 3.11+ и ключ Anthropic API (https://console.anthropic.com/).

```bash
cd quizflow_ai_service
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
cp .env.example .env
# впишите в .env свой ANTHROPIC_API_KEY

uvicorn app.main:app --host 0.0.0.0 --port 8100
```

Проверка:

```bash
curl http://localhost:8100/health
```

Интерактивная документация (Swagger UI) — `http://localhost:8100/docs`.

Фронтенд (`quizflow.jsx`) ходит сюда по адресу из константы `AI_SERVICE_BASE`
в начале файла — по умолчанию `http://localhost:8100`, меняется так же, как
`API_BASE`/`WS_BASE` для основного бэкенда.

## Единственный эндпоинт

`POST /api/generate-quiz`

Запрос:
```json
{
  "description": "квиз про историю Древнего Рима, для старшеклассников",
  "num_questions": 8,
  "mode": "simple"
}
```

- `description` — свободный текст, 3–1000 символов. Единственное
  обязательное поле.
- `num_questions` — 1–15 (лимит настраивается через `MAX_QUESTIONS_PER_REQUEST`
  в `.env`).
- `mode` — `"simple"` (один список вопросов) или `"topics"` (модель сама
  разобьёт на 2–4 подтемы).

Ответ — ровно та вложенная структура, которую ожидает `POST /api/quizzes/`
на основном бэкенде:

```json
{
  "title": "Древний Рим: от основания до империи",
  "category": "История",
  "mode": "simple",
  "topics": [
    {
      "title": "",
      "questions": [
        {
          "text": "В каком году, по легенде, был основан Рим?",
          "type": "single",
          "answers": [
            {"text": "753 год до н.э.", "is_correct": true},
            {"text": "509 год до н.э.", "is_correct": false},
            {"text": "27 год до н.э.", "is_correct": false},
            {"text": "476 год н.э.", "is_correct": false}
          ]
        }
      ]
    }
  ]
}
```

Медиа (фото/видео/аудио) модель, разумеется, не генерирует — вопросы
приходят без него; организатор при желании добавляет медиа уже после,
как и к любому вручную созданному вопросу.

### Коды ошибок

| Код | Когда |
|---|---|
| 422 | Пустое описание, слишком много вопросов — запрос отклонён ещё до обращения к Claude |
| 500 | Сервис не настроен (нет/неверный `ANTHROPIC_API_KEY`) |
| 502 | Claude ответил, но модель дважды подряд не смогла выдать корректный по структуре и правилам квиз — попробуйте переформулировать описание |
| 503 | Claude API временно перегружен/недоступен — есть смысл повторить запрос через некоторое время |

## Как обеспечивается надёжный JSON от модели

Используется официальный механизм Claude API — [Structured Outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
(`client.messages.parse(..., output_format=GenerateQuizResponse)`). Схема
собирается из Pydantic-модели автоматически и ограничивает генерацию на
уровне токенов (constrained decoding): модель физически не может выдать
JSON, не совпадающий по структуре и типам полей со схемой, — это гарантия
API, а не просьба в промпте, которую можно не выполнить. SDK сам
возвращает уже провалидированный экземпляр `GenerateQuizResponse` в
`response.parsed_output`.

Обратите внимание: модели с Structured Outputs (в том числе
`claude-sonnet-5`) не поддерживают préfill ответа (незавершённое
сообщение ассистента в конце диалога) — API в этом случае отвечает 400
`"This model does not support assistant message prefill."`. Все запросы
в `claude_client.py` заканчиваются сообщением пользователя.

Schema покрывает только СТРУКТУРУ (какие поля, какие типы) — смысловые
бизнес-правила (например, что при `type="text"` в `answers` должна быть
ровно одна запись с `is_correct=true`, а не ноль или пять) она не
выражает, поэтому они по-прежнему живут в `model_validator` в
`app/schemas.py` и могут не выполниться, даже когда структура формально
верна. Если валидация всё равно не прошла — делается ровно одна повторная
попытка с более настойчивой инструкцией, и только потом отдаётся 502.
Явный отказ модели (`stop_reason="refusal"`) не повторяется — просить то
же самое второй раз бессмысленно.

Валидация (`app/schemas.py`) намеренно дублирует те же правила, что и
`QuestionSerializer` на Django-бэкенде (у вопроса с выбором ответа минимум
2 варианта и хотя бы один правильный; у текстового — ровно один принимаемый
ответ) — так сгенерированный квиз гарантированно пройдёт сохранение там, а
не отвалится непонятной для пользователя ошибкой на последнем шаге.

## Тесты

```bash
pip install -r requirements-dev.txt   # requirements.txt + pytest/httpx
pytest
```

Реального `ANTHROPIC_API_KEY` для тестов не нужно и не должно быть —
вызов `anthropic.AsyncAnthropic.messages.parse` мокается, проверяется вся
остальная логика: сборка промпта, обработка отказа модели, повтор при
нарушении бизнес-правил, коды ошибок на уровне HTTP. Форма реально
отправляемого тела запроса (`output_config.format`) при желании
проверяется перехватом на уровне HTTP-транспорта (`httpx.MockTransport`)
без реального ключа и без обращения к сети.
